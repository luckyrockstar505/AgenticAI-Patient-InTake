# CLAUDE.md — rules for Claude Code in this repo

## What this project is

This is a demo AI agent for **medical claim intake**. The flow is:

1. Take the member ID and name.
2. Fetch coverage through an MCP tool.
3. Verify identity deterministically.
4. Show the policy.
5. Take the claim in natural language, asking follow-ups.
6. Confirm with the member and create a case.

The stack is LangGraph, FastMCP, FastAPI, LiteLLM → AWS Bedrock, Postgres, MLflow, Docker and GitHub Actions. The project follows the **BMAD** method.

## How to work a story

1. Work only on the story you were given, on branch `story/<id>-<slug>`.
2. Read the story file fully, including its Dev Notes, and the docs it lists.
3. Set the story's Status to `InProgress`.
4. Do the Tasks in order. Tick each checkbox as it's done, and write tests alongside the code.
5. Run `make lint typecheck test eval` and make sure everything is green before calling the story done.
6. Fill in the **Dev Agent Record**: model used, completion notes, and the **File List** of every file you created or changed.
7. Add a row to the Change Log and set Status to `Review`.
8. Don't edit other stories, the PRD or the architecture doc. If a change is needed there, write it under "Completion Notes → Proposed doc changes" instead.

## Hard rules (the safety invariants)

- The LLM **never** decides whether a member is verified or whether a case gets created. Tools do that (`mcp_tools/`).
- Policy data is fetched and rendered **only** when `state.verified is True`.
- Expected challenge answers, DOBs and full member IDs **never** appear in prompts, assistant messages, logs or traces.
- `create_case` needs verification `PASSED` **and** an explicit `confirm` intent in the `confirm` phase.
- Unknown member IDs are **never** revealed as unknown.
- Numbers in the policy and claim summaries are rendered from templates, not generated by the LLM.

## Coding conventions

- Python 3.12, `uv`, ruff (line length 100), mypy strict on `agent/`, `mcp_tools/`, `shared/`.
- Pydantic v2 for every boundary model. Keep async end-to-end in `api/` and `agent/`.
- All LLM calls go through `agent/llm.py:complete()` with a `purpose=`. Never import `litellm` anywhere else.
- All tool calls go through `agent/mcp_client.py`. Nodes receive `mcp` and `llm` by dependency injection.
- Prompts live in `agent/prompts/*.md` and are registered in the MLflow Prompt Registry.
- Tests use `LLM_MODE=mock` and the fake MCP. A test that touches the network is a bug.
- Frontend JavaScript in `api/static/` must be **ES5 only**: no arrow functions, no template literals, no `let`/`const`, no `fetch` streams, no `navigator.clipboard`.
- Use synthetic data only.

## Commands

```bash
make up | down | logs          # docker compose stack
make lint typecheck test       # quality
make test-int                  # integration (postgres)
make eval                      # mock conversation evals
make eval-live                 # Bedrock evals (AWS creds)
python -m agent.cli            # terminal chat
```

## Slash commands

- `/story <id>` implements a story (see `.claude/commands/story.md`).
- `/review-story <id>` performs QA on a story branch (see `.claude/commands/review-story.md`).
