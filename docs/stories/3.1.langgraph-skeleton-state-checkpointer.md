## Story

**As a** agent developer,  
**I want** the full graph wired with stub nodes, persistent state and a fake MCP client,  
**so that** every later node story just fills in a node.

## Acceptance Criteria

1. `agent/state.py` implements `AgentState` + `Phase` exactly as architecture §3.1.
2. `agent/graph.py` `build_graph(mcp, llm, checkpointer)` wires all nodes/edges in §3.2 with stubs returning canned messages.
3. `PostgresSaver` checkpointer, `thread_id=session_id`; conversation resumes across process restarts.
4. `agent/mcp_client.py` typed async client for all contract tools; `tests/fakes/fake_mcp.py` implements the same interface in-memory from seed JSON.
5. `python -m agent.cli` runs an interactive terminal chat (mock or bedrock).
6. Graph renders to Mermaid (`docs/graph.mmd`) via `graph.get_graph().draw_mermaid()`.

## Dev Notes

**Read before coding:** `CLAUDE.md`, `docs/architecture.md`, `docs/contracts/mcp-tools.md`, `docs/intents.md`, `docs/tracing.md`.

- Dependency injection: nodes get `mcp` and `llm` via closure/partial, so tests pass fakes.
- Use `interrupt()` or end-of-turn pattern consistently; document the choice in Dev Notes of this story after implementing.
- Fake MCP must pass the same contract tests as the real server (2.3–2.5).

**Chosen pattern: plain `END`, not `interrupt()`.** Every phase node (`intake`,
`verify`, `policy`, `claim_extract`, `clarify`, `confirm`, `handoff`) edges
straight to `END`; `router` is the only re-entry point and it re-reads
`state.phase`/`state.last_intent` from the checkpoint on every call. One user
message = one `graph.ainvoke()` = one turn, matching the `POST
/sessions/{id}/messages` API shape (architecture §8). `interrupt()` would be
for pausing *inside* a single invocation for human input, which this
request/response shape never needs. See "Design Notes" in the story spec for
the full rationale.

**Node "claim_extract" vs. field "claim":** the CLAIM phase's graph node is
registered as `"claim_extract"` (function is still `agent.nodes.claim.claim`,
per the Code Map's file name), because LangGraph rejects a node name equal to
an existing `AgentState` key (`claim` is already `AgentState.claim`). This
also matches `docs/tracing.md`'s `node.claim_extract` span name and
architecture §3.2's diagram label, so no naming drift versus those docs.

**Deviation from the spec's Code Map:** `agent/state.py` needed one import
fix, not left as pure passthrough. `from langchain_core.messages import
AnyMessage, add_messages` no longer resolves against the pinned
`langgraph==0.3.5` / `langchain-core==0.3.53` — `add_messages` now lives in
`langgraph.graph.message`, not re-exported from `langchain_core.messages`.
Fixed to `from langgraph.graph.message import add_messages` (kept
`AnyMessage` from `langchain_core.messages`). No field, no `Phase` value, no
semantics changed — this was a straight import-path bugfix required for
`agent/state.py` (and therefore anything importing it) to import at all.

### Completion Notes

- Implemented `build_graph(mcp, llm, checkpointer)`: `router` (regex cancel/handoff fast-paths only — no LLM intent classification yet, that's story 3.2) conditionally dispatches to one of 6 phase-stub nodes or `handoff`/`cancelled`(`END`); every phase node edges straight to `END` (see Dev Notes: "Chosen pattern").
- All 7 contract tools added to `agent/mcp_client.py` (`MCPClient`) with a real streamable-http `mcp` client transport, plus a shared `MCPClientProtocol` that both `MCPClient` and `tests/fakes/fake_mcp.FakeMCPClient` satisfy structurally.
- `FakeMCPClient` is a faithful in-memory implementation of all 7 tools from `data/seed/members.json`/`coverage.json`: unknown member IDs behave identically to known-but-wrong-answer members (no enumeration), `check_answer` tracks attempts per `verification_id` and locks at `MAX_VERIFY_ATTEMPTS=3`, `get_policy_view`/`create_case` gate on verification `PASSED`, `create_case` is idempotent per `session_id`.
- Checkpointer: `AsyncPostgresSaver`, `thread_id=session_id`, tables created via `await checkpointer.setup()` (no Alembic) — wired in `agent/cli.py`; `build_graph()` itself just takes any already-constructed checkpointer (tests use `MemorySaver`).
- **Windows-only fix (not a story requirement, needed to actually run/verify locally):** psycopg's async mode refuses the default Windows `ProactorEventLoop`. Added `asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())` in `agent/cli.py`'s `__main__` guard and in a new `tests/integration/conftest.py` (no-op on Linux/macOS/CI).
- Deviation from Code Map: fixed a broken import in `agent/state.py` (see Dev Notes above) — required for anything to import, not a semantic change.
- `docs/graph.mmd` is the committed `draw_mermaid()` output of the compiled graph exactly as built by `build_graph()`.
- Not implemented (explicitly out of scope per spec Boundaries): any real verification/extraction/LLM logic in nodes, `mcp_tools/` server-side tools (contract tools called by `MCPClient` don't exist server-side yet — that's stories 2.3-2.5; `mcp_tools/server.py` still only has `ping`), `request_callback` tool, and no Makefile/CI changes.
- Risk/left for later: `MCPClient.call_tool` opens a fresh streamable-http session per call (simplest correct thing for a skeleton with no live consumer yet); a later story may want a pooled/persistent session if per-call latency matters once `api/` actually calls it.
- Risk/observed but out of scope: `tests/integration/test_trace_no_phi.py` (pre-existing, story 1.4) fails on this Windows host with `mlflow.exceptions.MlflowException: file://...mlruns is not a valid remote uri` — an MLflow-on-Windows local-file-URI issue unrelated to anything touched in this story. Also note: if a `.env` copied from `.env.example` is present on the host (`MLFLOW_TRACKING_URI=http://mlflow:5000`), `tests/unit/test_health.py` hangs ~4-5 minutes on DNS resolution of the docker-only hostname `mlflow` before failing; with no `.env` present (or `MLFLOW_TRACKING_URI` unset) it passes in ~5s. Neither is new in this story; flagging since it's easy to trip over locally.
