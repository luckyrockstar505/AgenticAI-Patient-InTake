## Story

**As a** security-conscious product owner,  
**I want** identity verification decided by deterministic code,  
**so that** an LLM can never be talked into verifying the wrong person.

## Acceptance Criteria

1. `start_verification` and `check_answer` per contract §2–3.
2. Name match via rapidfuzz ≥ 90; DOB parsed from free text ("3/4/85", "March 4 1985"); ZIP first-5; employer/subscriber fuzzy ≥ 85.
3. Challenge question chosen randomly (seeded per session for reproducibility) from available fields, never repeating.
4. `MAX_VERIFY_ATTEMPTS` (3) → `LOCKED`; locked verifications reject further answers.
5. On PASSED, snapshot → `verified`; audits for every attempt, pass, lock.
6. Expected answers never appear in responses, logs or traces.
