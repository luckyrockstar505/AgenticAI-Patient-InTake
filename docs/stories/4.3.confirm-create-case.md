## Story

**As a** member,  
**I want** to review a summary and confirm before submission,  
**so that** my claim is accurate.

## Acceptance Criteria

1. Summary rendered via template listing every field (relative dates shown as absolute).
2. `confirm` → `create_case`; success shows case number and next steps; phase DONE.
3. `correct` → re-extract with correction, re-show summary.
4. `VALIDATION` error from tool → ask for the listed fields; `NOT_VERIFIED` → handoff (should be impossible; log `invariant_violation`).
5. Never creates a case without an explicit confirm intent in the confirm phase.
