Started with an existing brief for a Claims Intake Agent — a conversational AI that replaces the manual medical claim intake front door. The brief covered problem, solution, target users, MVP scope, and technical stack.

What happened

The Day 2 workshop cheat sheet was read and diffed against the brief. Key workshop rule: "a golden dataset is a spreadsheet, labelled by someone who does the job, never by the agent." The brief had no golden dataset spec at all.

What was added

New §5a with golden dataset schema, 20-build + 10-holdout split, seed data spec, and results.json export format. KPIs now reference the labelled example count. Layers summary added to §8.

PRD Fixes — Party Mode Decisions Done
Party mode round 2 · All 4 blockers resolved · prd.md updated
▾

Mary, John, Winston, and Sally worked through all 4 high-priority blockers with Srimaan. Every decision was made in the room and logged to .memlog.md.

A-1 ✓ Verification failure → callback flow. After 3 failures the agent says: "I wasn't able to verify your identity. Leave me a number and our team will call you back." Agent calls request_callback tool (writes member ID + session ID + contact number to callbacks queue). New state: PENDING_CALLBACK. No case created, no policy shown. Workshop scope: mock tool writes to Postgres callbacks table. ✅ resolved
A-2 ✓ Minor dependents in scope; adult dependents out. Subscriber may file on behalf of minor dependents. patient_name is required when patient ≠ subscriber. Adult dependent authorization (HIPAA permission check) is explicitly out of scope for MVP — too complex for workshop. ✅ resolved
A-3 ✓ No hard turn limit — partial case with flag. Removed "max 5 turns" magic number. Clarify loop asks for missing fields; if still missing, proceeds and creates the case anyway. create_case tool receives missing_fields[] and complete: bool. Member hears: "I'll submit your claim now — our team may follow up about [missing field]." No new state or tool needed. ✅ resolved
A-4 ✓ Required claim fields confirmed. Required: date_of_service · place_of_service · provider_name · diagnosis_reason · patient_name (when patient ≠ subscriber). Optional (collected if available): amounts · npi · accident_related · other_insurance. [ASSUMPTION] tag removed from FR-5.4. ✅ resolved

State machine — locked

UNVERIFIED → VERIFIED → (case created)
UNVERIFIED → PENDING_CALLBACK (3 failures → callback queue)
Any state → HUMAN_HANDOFF (member-initiated)
